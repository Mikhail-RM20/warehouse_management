# CheckStock — Где сейчас товар?

Веб-прототип складского учёта для фулфилмента (ФФ), реализованный на Python 3.13 с использованием FastAPI, SQLAlchemy (async), PostgreSQL и Docker. Приложение предоставляет веб-интерфейс (SSR на Jinja2) и набор HTTP-эндпоинтов для управления складами ФФ, оформления прихода, перемещений между складами, резервирования и отправки заказов по FBS, а также поставок по FBO.

---

## Принятые решения

* **Разделение остатков и движений (`StockItem` + `Movement`)**: физический остаток (`qty_on_hand`) и резерв FBS (`qty_reserved_fbs`) хранятся в разрезе пары `(product_id, warehouse_id)`, а показатель «Доступно» вычисляется динамически (`qty_on_hand - qty_reserved_fbs`). Это исключает рассинхронизацию остатков при отмене резерва или отгрузке.
* **Защита от двойного списания (`SELECT ... FOR UPDATE`)**: во всех критических операциях изменения остатков и подтверждения движений используется пессимистическая блокировка строк на уровне PostgreSQL. Повторное нажатие кнопки приёмки или отправки отклоняется проверкой текущего статуса движения без повторного списания или начисления товара.
* **Мягкое удаление складов (`Soft Delete`)**: при удалении склада ФФ запись не удаляется физически из БД, а помечается флагом `is_deleted = True`. Склад скрывается из форм выбора для новых операций, но все числящиеся на нём остатки и вся история движений сохраняются и отображаются с пометкой `удалён`.
* **Умная обработка нехватки на выбранном ФФ**: при попытке зарезервировать FBS, отправить FBO или переместить товар со склада с недостаточным доступным остатком система дополнительно проверяет суммарный доступный остаток по остальным активным складам и сообщает менеджеру точные цифры.
* **Паттерн Post/Redirect/Get (PRG) и единый перехват ошибок**: все POST-роуты возвращают `303 See Other` с редиректом на `/`, что защищает от повторной отправки формы по `F5`. Бизнес-исключения (`HTTPException`) перехватываются глобальным обработчиком в `main.py` и выводятся в виде баннера ошибки на главном экране.

## ИНСТРУКЦИЯ К ЗАПУСКУ

### ВНИМАНИЕ: `.env` файл
**Файл `.env` не хранится в репозитории — в проекте приложен шаблон `.env.example`.**

1. Создайте файл `.env` в корне проекта на основе `.env.example`:
   ```bash
   cp .env.example .env
   ```
   Содержимое `.env` для запуска в Docker:
   ```env
   POSTGRES_USER=Ваш логин
   POSTGRES_PASSWORD=Ваш пароль
   POSTGRES_DB=Ваша БД
   POSTGRES_HOST=postgres
   POSTGRES_PORT=5432
   ```

2. Запустите контейнеры:
   ```bash
   docker compose up -d --build
   ```
   При первом запуске приложение автоматически создаст таблицы в PostgreSQL и загрузит тестовые данные из ТЗ (`SKU-101`, `SKU-102`, `SKU-103` и склады «Север» и «Юг»).

3. После успешного запуска приложение будет доступно:
   * **Веб-интерфейс CheckStock:** http://localhost:8001

4. Остановка контейнеров:
   ```bash
   docker compose down
   ```
   *(Для полного сброса базы данных и повторной загрузки стартовых остатков из ТЗ: `docker compose down -v && docker compose up -d --build`)*

## Проверка складских сценариев

После запуска проекта на `http://localhost:8001` можно проверить все ключевые сценарии:

1. **Стартовые данные из ТЗ (Экран 01):**
   * `SKU-101` (Органайзер): Север — `10` (доступно `10`), Юг — `6` (доступно `6`).
   * `SKU-102` (Контейнер): Север — `5` (доступно `5`), Юг — `0`.
   * `SKU-103` (Корзина): Север — `0`, Юг — `4` (доступно `4`).
2. **Приход и перемещение между ФФ:**
   * Оформить приход и отправить перемещение между складами — остаток на складе-отправителе уменьшится сразу, а операция появится в блоке `02` со статусом `В пути`.
   * Нажать **«Принять на ФФ»** — статус сменится на `Завершено`, а товар зачислится на склад-получатель.
3. **Резерв, отмена и отправка FBS:**
   * Создать резерв FBS — физический остаток не изменится, увеличится колонка `В резерве FBS` и уменьшится `Доступно`.
   * При нажатии **«Отменить резерв»** товар вернётся в доступный остаток; при нажатии **«Отправить клиенту»** спишется физический остаток и резерв, а заказ перейдёт в статус `В пути` (`Едет к клиенту`).
4. **Поставка FBO:**
   * Отправить поставку FBO со склада ФФ — товар спишется со склада и появится в статусе `В пути` до нажатия **«Принять на МП (FBO)»**.
5. **Нехватка на выбранном ФФ при достаточном общем остатке:**
   * Попытаться зарезервировать или отправить со склада количество, превышающее остаток на этом ФФ, но меньшее суммы по всем активным складам — система заблокирует операцию и выведет сообщение с доступным остатком на выбранном ФФ и общим остатком на других складах.
6. **Переименование и удаление ФФ с остатком:**
   * Создать, переименовать и удалить склад с ненулевым остатком — склад получит статус `Удалён` и скроется из форм выбора, но его остатки и записи в истории операций сохранятся.
7. **Защита от повторного подтверждения:**
   * Повторный запрос на приёмку уже принятого перемещения/поставки FBO или повторную отправку FBS отклоняется ошибкой валидации статуса без двойного списания товара.

## Описание эндпоинтов

### 1. `GET /`
* **Что делает:** Отображает главный экран CheckStock со сводной таблицей остатков по складам ФФ, списком активных резервов FBS и товаров в пути, формами создания операций, управлением складами и хронологической историей всех движений.
* **Query Params:** `error` (опционально, строка) — текст ошибки бизнес-валидации для отображения в баннере после редиректа.
* **Ответ:** `200 OK` (HTML-страница `templates/index.html`).

### 2. `POST /warehouse/add/`
* **Что делает:** Создаёт новый активный склад фулфилмента (ФФ).
* **Form Data:** `name` (`str`, минимум 1 символ) — название склада.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `409` (склад с таким названием уже существует), `422` (пустое название), `500` (ошибка БД).

### 3. `POST /warehouse/rename/{warehouse_id}`
* **Что делает:** Переименовывает существующий активный склад ФФ.
* **Path Params:** `warehouse_id` (`int`) — ID склада.
* **Form Data:** `name` (`str`, минимум 1 символ) — новое название склада.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (некорректный ID или склад удалён), `404` (склад не найден), `500` (ошибка БД).

### 4. `POST /warehouse/delete/{warehouse_id}`
* **Что делает:** Выполняет мягкое удаление склада ФФ (`is_deleted = True`) с сохранением числящихся остатков и истории операций.
* **Path Params:** `warehouse_id` (`int`) — ID склада.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (некорректный ID или склад уже удалён), `404` (склад не найден), `500` (ошибка БД).

### 5. `POST /stock/inbound/`
* **Что делает:** Оформляет приход товара на выбранный активный склад ФФ и записывает операцию `INBOUND` в историю.
* **Form Data:** `product_id` (`int > 0`), `warehouse_id` (`int > 0`), `qty` (`int > 0`).
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (некорректные параметры или склад удалён), `404` (товар или склад не найден), `422` (ошибка валидации формы).

### 6. `POST /movement/transfer/send/`
* **Что делает:** Отправляет перемещение товара между двумя активными складами ФФ, списывает остаток со склада-отправителя и переводит движение в статус `IN_TRANSIT`.
* **Form Data:** `product_id` (`int > 0`), `from_warehouse_id` (`int > 0`), `to_warehouse_id` (`int > 0`), `qty` (`int > 0`).
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (склады совпадают, один из складов удалён или нехватка доступного остатка на складе-отправителе), `404` (товар или склад не найден).

### 7. `POST /movement/transfer/receive/{movement_id}`
* **Что делает:** Подтверждает приёмку перемещения на складе-получателе, зачисляет товар на остаток и переводит движение в статус `COMPLETED`.
* **Path Params:** `movement_id` (`int`) — ID перемещения.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (перемещение уже принято или отменено), `404` (перемещение не найдено).

### 8. `POST /movement/fbs/reserve/`
* **Что делает:** Создаёт резерв FBS на выбранном складе ФФ (`qty_reserved_fbs += qty`) и фиксирует движение в статусе `RESERVED`.
* **Form Data:** `product_id` (`int > 0`), `warehouse_id` (`int > 0`), `qty` (`int > 0`).
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (нехватка доступного остатка на выбранном складе или склад удалён), `404` (товар или склад не найден).

### 9. `POST /movement/fbs/ship/{movement_id}`
* **Что делает:** Подтверждает отправку зарезервированного заказа FBS клиенту, списывает товар из `qty_on_hand` и `qty_reserved_fbs` и переводит движение в статус `IN_TRANSIT`.
* **Path Params:** `movement_id` (`int`) — ID заказа FBS.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (заказ уже отправлен/отменён или несоответствие остатков), `404` (заказ FBS не найден).

### 10. `POST /movement/fbs/cancel/{movement_id}`
* **Что делает:** Отменяет активный резерв FBS, освобождая заблокированный остаток (`qty_reserved_fbs -= qty`) и переводя движение в статус `CANCELLED`.
* **Path Params:** `movement_id` (`int`) — ID заказа FBS.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (можно отменить только активный резерв `RESERVED`), `404` (заказ FBS не найден).

### 11. `POST /movement/fbo/send/`
* **Что делает:** Отправляет поставку FBO со склада ФФ на склад маркетплейса, списывает `qty_on_hand` и переводит движение в статус `IN_TRANSIT`.
* **Form Data:** `product_id` (`int > 0`), `warehouse_id` (`int > 0`), `qty` (`int > 0`).
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (нехватка доступного товара на складе или склад удалён), `404` (товар или склад не найден).

### 12. `POST /movement/fbo/receive/{movement_id}`
* **Что делает:** Подтверждает приёмку поставки FBO на складе маркетплейса и переводит движение из `IN_TRANSIT` в `COMPLETED`.
* **Path Params:** `movement_id` (`int`) — ID поставки FBO.
* **Ответ:** `303 See Other` → редирект на `/`.
* **Возможные ошибки:** `400` (поставка FBO уже принята или отменена), `404` (поставка FBO не найдена).
